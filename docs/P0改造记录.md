对应 `docs/差距分析.md` 的 P0 三项，全部落地并在真实浏览器上验证。

| 项 | 改动 | 文件 |
|---|---|---|
| 体积识别（206 兜底） | 解析 `Content-Range: bytes 0-1/1234567` 取总量，优先于 `content-length`（206 的 CL 只是分片长度）；记录 `accept-ranges` | `background.js` `classify()` |
| DRM 识别 | HLS `SAMPLE-AES(-CTR)`、DASH `ContentProtection` 判定为受保护；条目带 `drm/drmReason`，弹窗标红、下载按钮置灰 | `content.js`、`popup.js`、`background.js`（`vdh:flag`） |

## 两个踩到的实现坑（供后续参考）

1. **Chrome MV3 消息通道是 JSON 序列化**：内容脚本 `sendMessage` 传 `ArrayBuffer` 到后台，后台收到的是 `{}`，写入长度恒为 0。改成 base64 分块（2MB/块）才能正确落盘——但最终方案已改为内容脚本直写 OPFS，不再跨进程传数据。
2. **Service Worker 里没有 `URL.createObjectURL`**：后台拿到 OPFS 文件后无法生成 blob URL 交给 `downloads.download`。要么上 `chrome.offscreen`，要么把 OPFS 放在内容脚本侧（采用后者：`File` 句柄 + `<a download>` 本身就是流式，且 Firefox 同样适用）。
