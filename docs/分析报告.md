## 二、官方 VDH 的技术路线（拆 `extensions/{b9db16a4…}.xpi` 得出）

- MV3、`background.type=module`，权限比自建插件多：`webNavigation`、`scripting`、`declarativeNetRequest`、
  `notifications`、`contextMenus`、`unlimitedStorage`。
- `injected/` 下有 **26 个站点专用脚本**（YouTube、Bilibili、Vimeo、OK、Canva、Twitch、X/Twitter 等），
  逐个适配各家播放器；`content/smartnaming.js` 负责命名，`download_worker/` 负责落盘。
- 结论：VDH 的能力上限来自"站点适配"而不是"通用嗅探"。自建插件不可能复制 26 套站点脚本，
  所以提升重点只能放在**通用层的解析能力与下载链路鲁棒性**上——这也决定了本次改造方向。

## 三、原插件的问题清单（对照上面的结论）

1. **只有一份 Chrome 清单**：`background.service_worker` 是 Chrome 写法，Firefox 装不上，与用户实际浏览器不符。
2. **无法选清晰度**：HLS 永远取最高码率，720p/1080p/独立音轨/字幕都拿不到选择权。
3. **字幕完全忽略**：主播放列表里的 `EXT-X-MEDIA:TYPE=SUBTITLES` 被丢弃。
4. **多 iframe 的 MSE 捕获互相覆盖**：`mseState` 按 tab 存一份，子帧上报会顶掉父帧数据。
5. **任务状态不清**：下载结束后 `job` 一直留在后台，徽标永远显示条目数。
6. **防盗链只有"失败后回退"**：没有主动选择页内下载的开关；直链被 403 时要先失败一次才开始下载。
7. **文件名取自分片地址**：`master.m3u8` / `index.m3u8` 这类通用名会变成最终文件名。
8. **DASH 模板 `$$` 转义没处理**：`price$$.m4s` 这类地址会被错误保留。
9. **无测试、无打包、无文档**：改一处不知道会不会弄坏解析器。

## 四、本次改造内容

| 文件 | 改动 |
| --- | --- |
| `manifest.json` | 保持 Chrome/Edge 清单；请求类型补 `object` / `sub_frame`；媒体扩展名补 `vtt/srt` |
| `tools/build.mjs` | 新增打包脚本，由同一份代码生成 Chrome zip 与 Firefox xpi；Firefox 侧自动改写 `background.scripts` + `browser_specific_settings.gecko`（含 `data_collection_permissions`） |
| `background.js` | ①MSE 按 `frameId` 分帧存储并汇总；②HLS/DASH 清晰度清单缓存；③新增 `clearJob`、`vdh:variants` 消息；④徽标：下载中显示 `↓`，否则显示条目数；⑤字幕按 `sub` 类型单独归类；⑥直链回退只做一次，避免失败循环 |
| `content.js` | ①新增 `vdh:probe`：在页面上下文解析主播放列表，返回清晰度/独立音轨/多语言字幕；②`vdh:download` 支持 `variantUrl` / `audioUrl`；③新增 `vdh:sub` 字幕保存；④`fetchText` 加三次重试；⑤文件名遇到 index/master/playlist 等通用名改取页面标题 |
| `popup.js` `.html` `.css` | ①搜索框过滤；②每行清晰度下拉框（自动/各档位）；③字幕按钮；④「页内下载」开关（持久化到 `storage.local`），强制带 Cookie/Referer；⑤任务结束后主动清理后端 job；⑥探测失败 60 秒退避 |
| `lib/stream.js` | 修正 DASH 模板 `$$` 转义；导出 `fillUrlTemplate` 便于单测 |
| `test/parsers.test.js` | 6 组解析器单测（主/媒体播放列表、BYTERANGE、GAP、工具函数、模板变量） |
| `README.md` | 功能、目录、Chrome/Firefox 安装、校验命令、已知限制 |

## 六、后续可做（未在本次实现）

1. **音视频封装合并**：目前视频轨、音频轨分开保存，需要 ffmpeg 合并；若要做到"一次落盘可直接播放"，
   得在内嵌 Web Worker 里做 fMP4/TS 封装（或引入 mux.js）。
2. **DRM 判断**：检测到 `ContentProtection` / `SAMPLE-AES` 时给明确提示"受保护内容不支持"，
   而不是抛一个笼统的解析失败。
3. **站点适配层**：按需针对固定使用的站点写专用注入脚本（这是 VDH 的能力来源，但维护成本高）。
4. **直播录制落盘**：当前直播录制全在内存里（上限 2 GB），改为 OPFS/分片写盘可支持超长录制。
5. **Chrome 157 之后无法命令行加载扩展**：本地开发只能在 `chrome://extensions` 手点「加载已解压的扩展程序」。
