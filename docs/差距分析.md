# 与原版 Video Download Helper 的差距分析

取证对象：本机 Firefox 160 已安装的 **Video DownloadHelper 10.7.1.2**（AMO 版，MV3），解包于 `/tmp/vdhx/vdh`。
对照对象：本仓库 `video-download-helper`（Chrome/Firefox 双端共用）。

> 取证方式：对原版压缩产物做字符串与上下文定位（`service/main.js` 756KB、`download_worker/main.js` 172KB、`content/panel.js` 564KB），下文每条结论都附文件位置或函数名，可复现。

---

## 0. 结论速览

| 维度 | 原版 VDH | 本插件 | 差距 |
|---|---|---|---|
| 直链流字节数 | `content-length` **或** `content-range` 总量（206 也拿得到），另记 `supports_byte_ranges` | 只取 `content-length`（`background.js:235`），206/无该头 → `size=0` | **中** |
| HLS/DASH 字节数 | 检测阶段**也不显示字节**：`quality.size` 实为分辨率，面板渲染 `DEMUXER - 1920x1080 - 2.8MB/s`（`content/panel.js` 的 `Bw()`/`Ce()`） | 显示 `1080p · 2800kbps` | 基本持平（可超越） |
| 合并 | **wasm ffmpeg（libav 6.5.7.1，4.86MB）在 Worker 内真封装**，输出单个 mp4/mkv，音轨可选、字幕进容器、`-c copy` 不重编码 | **纯字节拼接**：TS→`.ts`、fMP4→`.mp4`，音轨单独出 `.m4a/.ts`，字幕单独 `.vtt` | **大（代差）** |
| 下载落盘 | OPFS 流式写盘 → `chrome.downloads.download`，GB 级不吃内存 | 全量 `Blob` 拼在内存 → `<a download>` | **大** |
| 重试 | 分片 6 次尝试 + 指数退避 + 读/取双超时 + 失败率阈值容忍 | 3 次尝试 + 350ms 线性退避，无超时、无失败率容忍 | 中 |
| 并发 | 信号量并发，受「最大并发下载数」设置控制，可 `throttle` 降为 1 | 固定 `total>24 ? 4 : 2`（`content.js:219`） | 中 |
| 进度 | ffmpeg 侧 `ffmpeg_get_total_size_bytes` 真实字节 + 输出时长 | 按分片计数（`onProgress{done,total}`） | 中 |
| 任务管理 | 队列、取消（`ffmpeg_interrupt`）、失败重试按钮、中断提示、子目录/重名策略/另存为 | 单任务、仅取消 signal、无队列/无重试入口/无子目录 | 中 |
| DRM 识别 | `has_drm` 标记 + 失败文案 | 无 | 小但影响体验 |
| 站点适配 | 26 个 `injected/*` 专用脚本（YouTube 1.2MB、facebook、ok 等） | 通用层（MSE 挂钩 + 网络嗅探） | 大但不可复制 |

## 1. 视频流识别（重点：总字节大小）

### 1.1 原版怎么做

- **直链**：在 `webRequest.onHeadersReceived` 里取体积，两条路都走（`service/main.js` 函数 `sD`）：
  ```js
  let s = n.get("content-length"), u = n.get("content-range");
  if (typeof u === "string") s = u.split("/")?.[1] || s;   // "bytes 0-1/1234567" → 取 1234567
  ...
  let m = n.get("accept-ranges") == "bytes" || n.has("content-range");  // 记 supports_byte_ranges
  ```
  → 服务器只回 206 时也能拿到**真实总字节**，并据此判断是否可做 Range 下载。
- **HLS/DASH**：`quality` 对象里 `size` 是**分辨率**（`{width,height}`），`bitrate` 是 `BANDWIDTH`：
  ```js
  l.attributes.RESOLUTION && (g = B({height:..., width:...}));
  l.attributes.BANDWIDTH && (p = B(l.attributes.BANDWIDTH));
  let S = { size: g, bitrate: p };     // service/main.js（HLS master 解析）
  ```
  面板渲染函数：
  ```js
  function Bw(e){ ... t.push(e.demuxer.toUpperCase()); ... `${i}x${o}`; ... Ce(bitrate)+"/s" }
  ```
  → 分段流在**检测阶段没有字节数**，只有「格式 - 分辨率 - 码率」。
- 字节数在下载阶段才出现：Worker 轮询 `ffmpeg_get_total_size_bytes()`（见 §3.4）。

### 1.2 本插件现状

- `background.js:235`：`const size = parseInt(headers['content-length'] || '0', 10) || 0;` —— 仅一条来源。
- 弹窗对 HLS/DASH 条目 `size=0`，因此不显示任何体积信息。

### 1.3 差距清单

| # | 差距 | 影响 | 修法 |
|---|---|---|---|
| 1 | 缺 `content-range` 兜底 | CDN 只回 206 的直链（很常见）体积恒为 0，用户判断不了文件多大 | 抄 §1.1 的两行解析；顺带记录 `acceptRanges` |
| 2 | 分段流无体积估算 | 与原版持平，但**这是唯一能超越原版的地方** | `Σ(EXTINF 时长) × BANDWIDTH / 8`；再用 2~3 个分片的 `Range: bytes=0-1` 抽样校准（同时验证 CDN 是否支持 Range） |
| 3 | 无 DRM 识别 | 下完才发现是加密分片/空文件 | 检测 `#EXT-X-KEY:METHOD=SAMPLE-AES`、`<ContentProtection>`、`widevine` 字样 → 条目标红并提示 |

> 结论：**"总字节大小"这项，原版对分段流同样不做前置估算**，它不是我们的落后项；真正的落后项是① 206 兜底，② 缺估算（可做出比原版更好的体验）。

## 2. 合并（多轨音视频 + 字幕落成一个文件）

### 2.1 原版怎么做：Worker 内 wasm ffmpeg 真封装

`download_worker/` 三个文件就是全部答案：

| 文件 | 大小 | 作用 |
|---|---|---|
| `libav-6.5.7.1-h264-aac-mp3.wasm.wasm` | 4,857,955 B | wasm 版 ffmpeg（只编 h264/aac/mp3 解码器） |
| `libav-…wasm.mjs` | 202,476 B | libav.js 胶水层 |
| `main.js` | 172,582 B | 封装/调度逻辑 |

封装入口（`main.js`）：

```js
let f = t.muxer == "mkv" ? "matroska" : t.muxer;
let m = { filename: a.output_filename, open: !0, codecpars: !0, device: !0, format_name: f };
await b.ff_init_muxer(m, d)            // 建封装器
b.avcodec_parameters_copy / av_dict_copy_js   // 把各输入流的 codec 参数直接搬进输出
```

三条流水线（按流形态自动选）：

1. **DASH** —— 直接把 MPD 交给 ffmpeg，由它自己解析分片模板：
   ```js
   ["-analyzeduration","10M","-f","dash","-mpd_video_idx",`${t.entry}`,
    "-i",`jsfetch:${t.url}`,
    "-map","0:v:0?","-map","0:a:0?",
    "-c:v","copy","-c:a","copy",
    "-avoid_negative_ts","make_zero","-y", r]
   ```
   音轨可按 id 精确挑：`["-map",`0:a:m:id:${audio_track_id}`]`，或 `-mpd_audio_idx` 指定节目。
2. **HLS** —— 同理 `"-f","hls","-i",jsfetch:<m3u8>`，`-c:v copy -c:a copy` 直通封装。
3. **字幕** —— 作为额外输入合进容器：
   ```js
   ["-i",`jsfetch:${vttUrl}`],
   ["-map","1:s:0?"],
   ["-c:s", muxer=="mp4" ? "mov_text" : "copy"],   // mp4 转 mov_text，mkv 直接内嵌
   ["-metadata:s:s:0",`language=${lang}`]
   ```
4. **纯音频** —— `-c:a libmp3lame` 转 mp3 单独出。

关键工程细节：`jsfetch:` 是自定义伪协议（`jsfetch_set_read_timeout` / `set_fetch_timeout` / `set_initial_retry_delay` / `set_bypass_cache` / `set_carry_params_from`），把 fetch（带 cookie、带站内参数、可绕缓存）喂给 ffmpeg —— **分片抓取这件事整体外包给了 ffmpeg**。

还有一个 `-t 3 -an` 的 3 秒「preview」用例：只抓开头 3 秒生成样本，用来在下载前验证链路能否封装成功。

### 2.2 本插件现状

`content.js` 下载完成后：

```js
const isFmp4 = ...; const ext = isFmp4 ? 'mp4' : 'ts';
parts.push(...videoResult.parts);
saveBlob(new Blob(parts, {type: isFmp4 ? 'video/mp4' : 'video/mp2t'}), buildName(base, quality, ext));
// 音频：另存 `${base} audio.m4a|.ts`
// 字幕：另存 .vtt（content.js:444）
```

即：**只做字节级顺序拼接，没有任何容器层操作**。

### 2.3 差距与后果

| # | 差距 | 后果 |
|---|---|---|
| 1 | 多轨不合流 | 用户拿到 2 个文件（视频 + 音频），必须自己 `ffmpeg -i v -i a -c copy out.mp4`；这正好是 90% 用户不会做的一步 |
| 2 | 字幕不进容器 | 播放器不会自动挂字幕（.vtt 与 .ts/.mp4 同名也只在部分播放器生效） |
| 3 | TS 原样存 `.ts` | ts 不是通用交付格式（剪辑软件、手机相册常不认） |
| 4 | fMP4 裸拼接 | 缺 `sidx`/`mfra` 修正与时间戳收敛，某些 CDN 分片序号不连续时首尾会飘、seek 失败；`-avoid_negative_ts make_zero` 这类收敛原版是做掉的 |
| 5 | 无「封装可行性预检」 | 分片编码不兼容/加密时，要下完整个文件才知道失败 |

### 2.4 三条可选补齐路线（按代价排序）

| 方案 | 体积/依赖 | 能做到什么 | 适用 |
|---|---|---|---|
| A. 内置 wasm ffmpeg（照抄原版形态） | +5MB 包体、需 CSP `wasm-unsafe-eval` | 与原版等价的 mp4/mkv 封装、音轨选择、字幕内嵌 | 想追平 |
| B. 轻量容器层（`mp4box.js` / `mux.js`） | 100~300KB | 只解决 fMP4 直通拼接、音轨合流、字幕 mov_text 写入；不含转码/TS 转封装 | 想低成本补 80% |
| C. 只改交互，不碰容器 | 0 | 下载后提示一键命令、或调用本机 ffmpeg（原生版才有） | 最小改动 |

> 现实建议：**B 为 P1 主攻**（把「双文件」变「单文件+可选字幕」），A 作为可选开关（默认关闭，用户点「合并为 MP4」时才加载 5MB wasm）。

## 3. 下载（并发、重试、断点、落盘）

### 3.1 并发

原版：

```js
function rt(t,e,r,i){ let n = t.throttle ? 1 : pn; return { semaphore: new ze(n), ... } }
```

- 信号量 `ze(n)` 控并发，`throttle` 时降为 1；`pn` 与设置项 `max_parallel_downloads`（「最大并发下载数」）联动。
- 双源 HLS 时把 video/audio 段数相加开信号量（`rt(t,e,i.length+o.length,!0)`），两路并行。

本插件：`const concurrency = Math.min(total > 24 ? 4 : 2, total);` —— 写死，不暴露给用户，也不随网络/服务端压力调整。

### 3.2 重试与容错

原版（Worker 侧，证据齐全）：

```js
globalThis.MAX_FETCH_ATTEMPTS = 6;  globalThis.MAX_READ_ATTEMPTS = 6;
globalThis.FetchWithRetry = Wi;     // 读、取两套重试
jsfetch_set_read_timeout / jsfetch_set_fetch_timeout / jsfetch_set_initial_retry_delay

// 分片失败容忍
if (o.type == "bad_segment") return e.failures.count++,
    e.failures.count / e.total_segments > dn ? 放弃 : "skip";   // 跳过坏分片继续
if (o.type == "decryption_failed") ...
// 退避
for (let a = 0; a < Br-1 && !n.isOk(); a++) await sleep(_n * a);
```

即：**6 次尝试 + 指数退避 + 超时 + 坏分片跳过（按失败率阈值熔断）**，错误分类到 `bad_segment` / `decryption_failed` / `e4XX_5X` / `user_abort`。

本插件（`content.js:128`）：3 次尝试、`350ms*(attempt+1)` 线性退避、**无超时**、**任一坏分片直接抛错整个任务失败**、无错误分类。

### 3.3 落盘

原版（`download_worker/main.js` + `service/main.js` 联动）：

```js
// 边下边写 OPFS
await ce.open(n.output_filename);                  // FileSystem 写句柄
... 
// 收尾：OPFS 文件 → Blob URL → downloads API → 清 OPFS
let fh = (await (await navigator.storage.getDirectory()).getFileHandle(name)).getFile();
let url = URL.createObjectURL(new File([fh], name, {type: "video/x-matroska"}));
browser.downloads.download({ url, filename: subdir + basename + "." + ext,
                             conflictAction: "uniquify", saveAs: save_as });
await (await navigator.storage.getDirectory()).removeEntry(name);
```

好处：**内存恒定**（GB 级视频也不炸）、失败可保留半成品、`subdir`/`uniquify`/`saveAs` 都可控、可以生成 3 秒预览样本。
代价：多一份磁盘副本（写完即删）。

本插件（`content.js:254`）：

```js
function saveBlob(blob, filename){ const url = URL.createObjectURL(blob); ... <a download> }
```

**全量数据在内存**里拼成 Blob。估算：1080p 30 分钟约 1.5GB → 分片数组 + Blob 双份驻留，标签页极易 OOM；且 `<a download>` 拿不到子目录、冲突策略、进度。

### 3.4 进度与任务管理

原版：

```js
// ffmpeg 路径：真实字节 + 输出时长
let y = await o.ffmpeg_get_total_size_bytes(); i.add_bytes(y - l);
let p = await o.ffmpeg_get_out_time_ms();      i.set_duration_in_s(p/1e3);
// 分片路径：按 duration_s 累积
e.duration_s += t.duration_s; progress_tracker.set_duration_in_s(e.duration_s)
```

另外有：任务队列（`next_download`、`max_parallel_downloads`）、`retry_download_button`（失败一键重下）、`download_interrupted`/`download_failed` 分类文案、取消走 `ffmpeg_interrupt()`、`known_segments_url` 去重、`cache`/`bypass_cache` 控制。

本插件：`onProgress({done,total,bytes,phase})` 按分片计数，弹窗显示进度条；取消靠 `AbortController`；无队列、无重下按钮、无中断分类文案。

### 3.5 断点续传

原版：**没有跨会话续传**（`download_interrupted` 的文案明确说「可能不完整」）。但有分片级重试 + OPFS 半成品 + 重试按钮，实际容错不弱。
本插件：无（失败即从 0 重来）。

## 4. 其它缺口（不属三条主线，但影响完成度）

| 项 | 原版 | 本插件 |
|---|---|---|
| 站点适配 | 26 个 `injected/*`（youtube 1.2MB 带签名/DRM/多音轨、facebook、ok.ru…） | 通用层，无站点脚本（不可复制，方向正确） |
| 智能命名 | `content/smartnaming.js` **1.5MB**，标题/画质/站点/时间戳多层规则 | `sanitizeFilename` + 标题+画质 |
| 下载前预检 | `-t 3` 3 秒样本验证封装链路 | 无 |
| 历史/列表 | 下载历史面板、100 条提示、清空已完成 | 无 |
| 设置持久化 | 首选画质、最大并发、下载目录/子目录、字幕语言、弹窗尺寸、字体大小 | 无设置页 |
| DRM | `has_drm` + 专门失败文案 | 无 |
| 国际化 | `_locales` 多语言 | 中文硬编码 |
| CSP | `script-src 'self' 'wasm-unsafe-eval'`（为 wasm） | 未开（若要上 wasm 必须加） |
| 权限 | `webRequest`+`declarativeNetRequest`+`unlimitedStorage`+`<all_urls>` | 同类但更窄，隐私侧更好 |

| 优先级 | 项 | 状态 |
